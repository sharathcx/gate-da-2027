# Revision material production SOP

## Required visual style

The primary sheet for each topic must follow the user's supplied compact Counting reference: one dense portrait page with a navy title banner, multiple narrow columns, numbered pastel panels, fine borders, serif type, prominent formulas, short worked examples and compact PYQ solutions. Use the space efficiently and keep text legible. Avoid large illustrations and oversized empty panels. Add a second compact page only when the topic needs it for readable coverage.

Write Markdown sources and generate matching PNGs with built-in ImageGen. Keep checkpoints and full-question solution sheets in the established folders. Expanded lessons can support the primary compact sheet where explanation is needed.

## One topic at a time

1. Map the topic to the official GATE DA 2027 syllabus and its prerequisites. Identify a small set of useful methods and misconceptions.
2. Read relevant official papers and their final keys. Record year, question number, PDF page, answer, and any modeling assumption. Mark paraphrases explicitly.
3. Filter the supplied question bank and other-exam archive against the syllabus. Label other-exam questions as supplements; record uncertain provenance instead of guessing. Community references help locate material and do not override an official key.
4. Write editable Markdown first. For each method, include when it applies, a formula with conditions, a worked example with intermediate steps, and a common trap. Teach every method used by the core checkpoint.
5. Generate compact, legible PNG lesson pages with built-in ImageGen in the user's reference style. Inspect equations, symbols, counts in diagrams, spacing, margins, and text. Correct any discrepancy before delivery.
6. Create an answer-free checkpoint. Clearly distinguish official PYQs from authored practice. Use MCQ/MSQ/NAT labels only where appropriate; written fraction responses are short-response practice.
7. Prepare separate solution pages, as requested by the user. Repeat the entire question and all choices, then show the reasoning and answer. Store them alongside lessons and checkpoint, without a separate checkpoint directory.
8. Independently check numerical answers and formulas, compare the final PNGs to the Markdown, and resolve all local image links. Confirm the ordered PNG filenames support one print job.
9. Update only material readiness. Study hours, attempts, scores and completed days require the user's check-in. Record unresolved errors before proceeding.

## Folder and print contract

Each topic has `Markdown/` and `PNG/`. Keep lessons, checkpoint and solution pages in those two folders. Use continuous page numbering so printing all PNGs gives lessons, questions, then answers. Do not create PDFs. Save revised prior editions in the revision archive so the active folder contains one current edition.

## Progress and timing

The target remains 90+ marks. The baseline is 4–5 focused hours per day with a maximum of four focused days per subject. This is a revision plan based on prior lecture completion, not a guarantee of a score or finish date.

If a topic takes longer, reduce optional enrichment first and rebalance the remaining hours. At the four-day cap, report any unfinished required coverage explicitly; never mark it complete merely because its time budget ended.

## Check-in format

Date; actual focused hours; pages studied; checkpoint answers and working; questions guessed or missed; next-day availability. Use reported evidence to choose the next task and update the error log.
